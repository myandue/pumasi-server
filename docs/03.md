# 03. 방(농장 여럿)·방문·채팅

## 범위
- 여럿, 사람마다 농장(방) 1개.
- DB·로그인 없음. 오프라인 농장 방문 없음.
- 큰 변경 건: 전역 farm 하나 -> 농장 여러 개(주인별).

## 데이터 (구조 변경)
- 현재: `Tile farm[6][6]` 전역 하나 / clients는 fd로 구분.
- 변경: 농장을 여러 개로. 
```
struct Farm { Tile tiles[6][6]; };
unordered_map<int, Farm> farms; // (키 = 주인 id)
``` 
- Client에 "지금 어느 농장 방에 있나" (current_farm = 주인 id) 추가. 자기 농장 id = 자기 id
- 접속하면 farms[my_id] 생성 + 자기 농장 방에 입장.

## 방 개념 (chat-server에서 가져오는 것)
- chat-server의 room = 여기서는 농장.
- 한 사람은 한 번에 한 방(농장)에만 있다.
- broadcast는 같은 방에 있는 사람에게만 (위치·타일·채팅 전부).
- 주인이 나가면(접속 끊기면) 그 방의 방문자들은 본인 방으로.

## 패킷
- 1~4: 일반
- 10~13: 클라->서버, 농사 액션
- 20~21: 서버->클라, 밭 정보
- 30~31: 클라->서버, 경제 요청
- 40: 서버->클라, 경제 알림
- 50번대: 클라->서버, 다른 사람 농장 방문, 자기 농장으로 돌아가기, 채팅 보내기
- 60번대: 서버->클라, 방문 가능한 유저 목록, 채팅 브로드캐스트, (다른 사람 농장 입장 시) 그 농장 스냅샷
- 바뀌는 것: 
    - PKT_SNAPSHOT (3): 위치를 "같은 방 사람"만 담아, 그 방 사람에게만 전송 (전원 x)
    - PKT_TILE_UPDATE (20): 요청자 1명 -> "그 방 전원"에게 전송
    - PKT_FARM_SNAPSHOT (21): 맨 앞에 [owner_id: uint32] 추가. 접속 시 1회 -> "방에 입장할 때마다".
        - payload: [owner_id: uint32][server_now: uint64] + 36칸 * [state:1][crop:1][stage:1][watered_at:8]

- 클라 -> 서버
    - PKT_VISIT (50), payload 4byte: [owner_id: uint32] // 방문 농장 id
        - 그 주인의 농장 방으로 이동. 자기 농장으로 돌아가기 = VISIT(내 id)
    - PKT_CHAT (51), payload = 메시지 바이트 (길이는 프레임 헤더에)
- 서버 -> 클라
    - PKT_PLAYER_LIST (60), payload: [count: uint16] + count * [id: uint32]
        - 방문 가능한(접속 중인) 유저 목록. 접속·퇴장으로 목록이 바뀔 때마다 전송
    - PKT_CHAT_MSG (61), payload: [sender_id: uint32] + 메시지 바이트
        - 같은 방 전원에게 브로드캐스트

## 서버 검증 (소유권 규칙)
- 주인/방문자 분리 필요. 행동 대상 = "지금 내가 있는 방의 농장"(farms[c.current_farm]).
- 갈기·심기·물: 방문자도 가능 (그 방 안이면 누구나)
- 수확: 그 농장 주인만 (`c.current_farm == my_id` 일 때만)
- 물주기 성공 시, 내가 방문자면(그 농장 주인이 아니라면) 코인 +2G -> 지갑 갱신
- 나머지 검증(크기·밭 영역·거리·상태)은 01과 동일
- 행동 성공 시 TILE_UPDATE는 그 방 전원에게 전송 

## 01·02와 연결
- `handle_farm_action`이 전역 `farm` 대신 `farms[c.current_farm]`을 대상으로.
- 물주기 성공 시 방문자면 +2G.
- `on_tick` 위치 스냅샷을 방별로 나눠 전송.
- 방문자가 심으면 방문자 씨앗 차감.
- 수확은 주인만. (주인 인벤에 적재)
